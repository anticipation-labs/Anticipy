## Release safety decisions

- Removed automatic signing-certificate revocation. The old helper selected
  every DEVELOPMENT certificate named `Created via API` without establishing
  orphan status. Attempt signing normally; stop on pool exhaustion for a
  certificate-specific decision. Temporary signing-key files use private mode.
- Do not run the default API deployment workflow: its post-deploy probe
  creates/deletes synthetic accounts and invokes account reset.
- An API-only release is compatible with this iOS patch and the older brain.
  New routes are additive, and new event/CAS guards require no new D1 columns.
  Verify existing schema prerequisites and deployed operational settings
  before any API deployment. Preserve deployed vars; `--keep-vars` alone does
  not prevent config-defined values from overwriting live values.
- Do not run the default brain workflow: it reads allowlisted owner memory,
  defaults the cap to one and immediately refreshes shared containers.
  Expected-source reconciliation can restart other owners even with a gradual
  platform rollout. Shared rollout requires a deliberate scope decision;
  unrelated customer data and account resets are not part of verification.
- Automatic OAuth-to-existing-task continuation remains deferred. Connect
  first and create a fresh read task; deliberately cancel an older equivalent
  before replacing it. Do not present connection success as task completion.
- API writes retain their existing closed maturity gate. No approval or
  authority boundary is loosened for the release.
