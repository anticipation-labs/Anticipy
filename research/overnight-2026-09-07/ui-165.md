# Connection links must be usable in the app

Build165 makes web addresses tappable in assistant answers, questions and expanded
capture details. These surfaces previously used plain SwiftUI strings: a valid
connection link could be visible without being a usable link.

Foundation detects URL syntax and adds link attributes to the unchanged text.
Only HTTP/HTTPS addresses are activated. No message meaning is classified, no
hidden Markdown destination replaces the displayed address, and nothing opens
until the owner taps it. The detector is reused on the main actor rather than
being allocated for each message render.

Verified on the actual simulator build165: an isolated, phone-less fixture received
`Open this test page: https://api.anticipy.ai/api/health`. The address appeared as
a link in Today. Tapping it opened Safari, which displayed the live API health
JSON. The back-to-Anticipy control returned to the same conversation, with the
composer available and listening stopped. No account was connected or message
sent to a real person. The CUA interaction and screenshots are in this thread.

The Foundation API probe additionally preserved the complete original string,
emoji and exact query parameters while excluding terminal sentence punctuation
from the link target. Both the full pre-edit and post-edit iOS logic suites pass;
the simulator build succeeds. Logs: `work/audit/overnight-165-baseline-ios.log`,
`work/audit/overnight-165-final-ios.log`, `work/audit/overnight-build-165.log`.
