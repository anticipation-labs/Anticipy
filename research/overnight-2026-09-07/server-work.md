# A result must fulfil the task before it can be completed

The live Avery draft request produced a public web answer about making a
SharePoint draft, then marked the task done. SharePoint was not requested.
The router permitted contextual drafting on the research lane, but that
executor only searched and summarized. Its completion check treated a URL
in the returned prose as independent success evidence. These were mismatched
capabilities and an inadequate result check, not a missing drafting keyword.

## Repair
The server executor asks one model question about its usable approach:
compose from the supplied record, research public facts, ask for missing access
or owner-only choices, or report an unavailable judgement. It produces the
actual private artifact when composition is enough. Search is not required
merely because a task was routed to the server. The router's capability
explanation now matches that executor.

A separate model question reviews fulfilment against the original authority,
current task, related memory and actual retrieved source content. URLs and the
candidate's own claims do not prove completion. The server cannot complete a
consequential workflow as text. Unlicensed hand notes cannot become searches.
A malformed or unavailable judgement never produces a completion receipt.

An incomplete composed answer gets one correction attempt from the same
context, followed by another review. Failure remains visible without claiming
an action. A private-source access blocker parks the same workflow in
needs_user. No real account read, send, booking or write is claimed by this
executor. Completion evidence records the exact stored text digest and actual
retrieved source URLs; the text bound is applied before verification and hashing.
