# Build 163 — browser status reflects the current connection

Using the actual simulator revealed “Not connected” beside an old “Browser
connected” success message and the old pairing code. The success belonged to
a previous attempt; the server record had already been disconnected.

The status row now owns success feedback. Connection changes clear the old
attempt/code. Disconnection shows progress, suppresses double taps and displays
an error if the server cannot complete it. Account changes fence delayed UI
updates. Both project build declarations move to163 in the same source commit.

Verified before shipping:
- The full iOS logic suite passed (`work/audit/overnight-ios-163.log`).
- Simulator build succeeded (`work/audit/overnight-build-163.log`).
- Actual iOS pairing + shipping registration/heartbeat + local Worker/D1:
  one registration despite three callers, exact owner matched, UI showed Ready.
- Disconnected through the app: Not connected, empty code, no old success text;
  old agent credential returned403. `pairing-163-results.json` records the wire.
- The local workerd process unexpectedly exited during the initial attempt.
  The UI reported the service error honestly. Restarting the local test service
  and retrying the same code succeeded. This is not evidence of a production
  outage; its local cause is not yet established.
