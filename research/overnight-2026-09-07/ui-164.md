# Listening session repair — build 164

The simulator reproduced old completed answers appearing as current listening
work. A capture now snapshots existing record IDs, retaining unfinished tasks
and displaying new replies without relying on the phone/server clock matching.
Pausing preserves that boundary. Ending a capture starts a new boundary.

A second reproduction occurred on relaunch: listening resumed before the first
history read returned. The session now records the first successful reply
snapshot separately and clears it at an account boundary. Loading that history
does not replay its replies as new capture results. Those answers remain in
Today. A result already present in the first history snapshot is history for
this purpose, even if it completed while the initial request was in flight.

- A 3,119-character result arriving through the local API appeared as a bounded
  card, with the full detail available separately and capture controls visible.

  this check; its capture-mode guard was corrected before release.
- Cold relaunch while listening: history replies stayed hidden after loading.
- Done returned to Today and stopped the microphone.
