# DEFINITION OF DONE — the finish line (never shrink it)

## Full product done

A real stranger (not Omar babysitting it) goes to the hosted Anticipy site, sees a Download button,
downloads the branded **Anticipy Execute** app, opens it, completes onboarding, connects
Chrome/accounts/extension, lets it build a profile, then uses the main app in real life — and trusts it.

All of this must work:

1. **Download:** hosted site has a clear download button for Anticipy Execute.
2. **Install/open:** the app opens without a developer terminal.
3. **Onboarding:** asks a few questions, installs/connects the Chrome extension/local bridge, explains permissions.
4. **Profile build:** opens the user's own logged-in Chrome, discovers/scrapes authorized sources, builds a profile.
5. **Clarification:** asks/calls the user for missing or uncertain facts.
6. **Connection mesh:** maps the user's tools — Gmail/Outlook, Calendar, CRM, Slack, LinkedIn, Amazon, legal/accounting.
7. **Main page:** Start Listening, paste a transcript, upload MP3/audio; live mic/device later.
8. **Active listening:** one engine processes everything (transcript, MP3, mic, SMS, browser, email, calendar, CRM).
9. **Memory:** remembers people, commitments, preferences, work context, and unresolved loops.
10. **Intent:** detects real tasks even when not phrased as commands (incl. implied/third-party tasks).
11. **Vents/jokes:** never acts on vents, sarcasm, jokes, emotional noise.
12. **Prepare and park:** performs harmless prep automatically; parks the irreversible step.
13. **API arm:** acts through direct integrations when available.
14. **Browser arm:** acts in the user's real Chrome when APIs are missing; stops before submit/pay.
15. **Voice/text arm:** closes loops by text/call ("the calendar hold is ready"; the 2:45 call rings).
16. **Receipts:** proves actions by independently re-reading artifacts.
17. **Five-day proof:** the user lives with it five real days and trusts it.

## What does NOT count as done

- "The engine could do it." · "The test is green." · "The builder says it works." · "It worked in a mock."
- "The UI exists but isn't wired." · "The browser agent can read but not prepare."
- "The app builds but a normal user can't download/open it." · "Transcript works but the memory/action handoff doesn't."

## Receipt standards (a receipt is human-openable)

- Calendar event re-read by ID. · Gmail draft re-read by ID.
- Browser page screenshot + DOM + URL proving cart/form prepared, with a guard log showing no submit/buy/pay.
- Phone/SMS provider SID + status read back. · Profile facts with source links + confidence.
- App download installed + launched. · Test transcript with expected-vs-actual incl. false-actions and misses.

**No receipt, no done.**
