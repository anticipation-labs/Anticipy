## The incident you slept through

The backend volume hit 4999.9/5000 MB and PocketBase could not write ANY
row — HQ crons failing every 5 minutes, transcript writes failing, signups
and password resets would have failed. Found via worker logs while deploying
the Mac hosting.

Cured at 09:58 PT: the boot script now drops the request-log DB and trims
the older scheduled backup snapshot before serving. **4.2 GB freed**
("free after backup trim 4221364KB" in the boot log). Zero disk-full errors
since. The deploy that carried the fix also serves the Mac download.

Why the three earlier deploys failed: the repo `.railwayignore` excludes
`backend/`, so `railway up` from the repo root or even from backend/ (whose
walk-up applies the root ignore) produced an archive with no Dockerfile —
"couldn't locate the dockerfile at path Dockerfile in code archive". Backend
deploys must run from a clean staging dir containing Dockerfile, start.sh,
pb_hooks, pb_migrations, pb_public. This is now documented here; a follow-up
should make it a script (`backend/deploy.sh`).
