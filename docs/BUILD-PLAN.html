2State of the machine

What already runs, and why this plan exists.

The evidence base is the pattern, not an incident: months of dated failures recorded in the code's own comments — an invented restaurant pursued for 58 steps, actions taken on dictated text, a held card that sat silent until its owner approved work he'd never been told about, uninvited-text evenings, and a decision lane that structurally could never ask a question — plus a field study of every shipped ambient product (where this system grades ahead: the approval gate, the browser hands' intent journal, memory provenance; and below the floor: hearing, and knowing who spoke).

Live now on the worker (each verified against the live service, each with tests): worked examples + a declared effect-channel in the judge's prompt · computed answers for computable questions · a provenance guard on outgoing names · a floor under act-minting fragments · a conversation posture with a single after-conversation digest · a governed ask valve (real quiet, daylight, capped, deduped, recorded) · a frontier-model second opinion on anything about to become an action. Judgment measured 68% → 80% on the labeled set.

What this plan finishes: the five organs below — because the machine walks, and now each organ has to be good.

3The five organs — how each gets done

Each block mirrors a card on the board. Owner, dependencies, today's state, done-when, options ranked.

EARS — hear whole thoughts, not fragments

Owner JoseOrder first — everything downstream is capped by itDepends on nothing

Today: a dictation-grade recognizer with no voice-activity detection and no true spoken-at timestamps; capture quality is the measured floor of the whole system. Done when: speech is captured with real timestamps, conversations emit close events, and judgment runs on finished thoughts.

A · RECOMMENDEDMigrate to Apple SpeechAnalyzer/SpeechTranscriber (long-form, multi-speaker, on-device — keeps the local-first law), fronted by its built-in voice detection, with capture-time stamps and segment-close events per CAPTURE-ARCHITECTURE.md.
B · FallbackKeep SFSpeechRecognizer; add Silero VAD + spoken_at plumbing + an on-device semantic endpointer. Smaller change; dictation-grade errors remain.
C · RejectedCloud streaming ASR. Most accurate, fastest — and raw audio leaves the phone, which is against standing law. Only ever a temporary flagged fallback.

SORTER — judge closed conversations, and whose task it is

Owner JoseOrder after EARS ships close eventsDepends on EARS

Today: judgment is line-by-line — context-blind by construction, patched by a fragment floor that is marked as tape. Done when: each closed conversation gets one strong-model judgment with its participant list (voice tags as hard evidence), the tape is deleted, and the labeled set + call replay do not regress. This also cuts ~50 cheap model calls per conversation to ~3 — cheaper and smarter.

LIBRARY — memory that survives a life

Owner JoseOrder anytime, parallelDepends on nothing

The model, plainly: three tools layered — the vector finder (fuzzy: "tooth guy" finds dentist), the graph (precise: which Laura), and ranking (fresh × important × relevant picks the five cards that matter now). The graph with provenance already exists. Done when:

  • Facts expire — "we broke up" retires "partner is Sarah" (kept for audit, excluded from recall), and situation-facts decay without reinforcement.
  • Confidence is read — it is stored today and consulted by nothing; doctrine says importance gates, confidence orders.
  • Origin gates action — owner-said may act; overheard may prepare; imported text (a calendar title) may be quoted, never obeyed.
  • The vector channel exists beside keyword and graph.

HANDS — research first, skills cached, APIs preferred, browser safe

Owner Jose (three cards)Order research card anytime; API and browser after itDepends on skills cache feeds the other two
  • Research + skills: deep research precedes any world-touching plan (server-side, cheap), and every successful run writes its recipe — site, steps, gotchas, last-verified — into a skills cache recalled before the next similar goal. Never pay for the same learning twice.
  • The API ladder: onboarding offers account hookups (mail, calendar, Slack, Notion…); APIs are preferred over driving websites; a repeated browser chore triggers "want to hook up the API so this is instant?" First step is research — Composio is the named candidate, not the decision.
  • The browser: safe (never touches credential or payment fields; journals intent before every click — already built), remembering (skills + library in its context, provenance respected), cheap (recipes before re-thinking; strong model only at decision points; screenshots captured as evidence).

A model grading a model is worthless; artifacts only. The app is the receipt drawer; texts are the interface.

5The rules — binding

1 · No pattern-match decides meaning.

Regexes and word lists never decide what words mean. Meaning belongs to a model with context. Legal pattern-matching: senses, the effect-channel seatbelt, deterministic tests.

2 · Tape ships only with an expiry

— a TAPE: comment naming the real fix and a red check tracking removal.

3 · Nothing is fixed until verified against the LIVE system.

Repo-green is a claim. Fingerprints and byte-diffs are facts.

4 · State lives in files, never in conversations.
5 · Fix order: senses → context → examples → model tier → structure.

A rule written while she is deaf, blind, untaught or under-modeled is tape by definition.

6 · The owner is not the review loop.

Nothing ships until an adversarial pass has tried to kill it.

6Done — the definition nobody may redefine

Done is when she's forgettable and nothing falls. A cold stranger onboards on their own accounts, lives a normal unscripted week, gets real things caught, never says "what?", never checks on her — and doesn't want to give it back. The test set is next week's life, which cannot be gamed.

The daily metronome: every morning, one question — was yesterday clean? Not clean → fix the one thing that broke it, then stop. Clean → touch nothing. No demo, green suite, or session may declare done; only lived days.
