# Agent Recipes — how four frontier systems drive a browser

Research date: **2026-06-03**. Sources cited inline. Purpose: extract the recipe
**shared** across all four systems, then copy ONLY those general mechanisms into
our existing loop (`engine/anticipy_engine/agent/webvoyager.py`). **No new
architecture. No site-specific logic. Keep our MV3-extension transport.**

---

## 1. Per-system summary

### Anthropic — Claude for Chrome / computer use
- **SEE** — `computer use` (API) is **pure pixels**: screenshot in, element refs are **(x,y) coordinates** in `display_width_px/height_px` space; no DOM, no set-of-marks. The **Claude for Chrome** extension uses **both** screenshots (via `debugger`) **and** DOM/text (via `scripting`). `zoom` action re-views a small region at full res for tiny text. (platform.claude.com/docs/.../computer-use-tool; claude.com/blog/claude-for-chrome)
- **CLICK** — vocab: `screenshot, left_click, type, key, scroll, *_click, drag, hold_key, wait, zoom`; **coordinate-based**. The model only *emits* the action — "your application must explicitly run the tool; Claude cannot run it directly." Trust level depends on the executor (Chrome ext = debugger/CDP). (computer-use-tool docs; anthropic-quickstarts computer_use_demo)
- **PLAN/MEMORY/LOOP** — agent loop (`tool_use` → `tool_result` → repeat) with an explicit **max-iteration cap** "to prevent infinite loops…and unexpected costs" (sample default 10). Memory = full message history incl. screenshots + **interleaved thinking** carried between steps. **Context management**: rolling buffer of the N most recent screenshots, **replace older images with text placeholders**, compact/summarize past a threshold, prompt-cache the stable prefix. **Verify-after-act**: "after each step, take a screenshot and carefully evaluate if you have achieved the right outcome…Claude sometimes assumes outcomes without checking." When an element won't cooperate (dropdowns/scrollbars), **switch to keyboard/DOM instead of clicking**. (computer-use-tool docs; claude.com/blog/best-practices-for-computer-and-browser-use)
- **HANDOFF** — per-site permissions (**Allow once / Always allow / Decline**). **Always-confirm** for purchases/financial/publishing/sharing personal data/deleting/creating accounts/**inputting sensitive info**. **Prohibited** from bypassing CAPTCHAs and entering sensitive data. Injection classifier → steers the model to **ask for confirmation** before the next action. Hard-blocks finance/adult/piracy categories. (support.claude.com/.../claude-in-chrome-permissions-guide; anthropic.com/research/prompt-injection-defenses)

### OpenAI — Operator / CUA / computer-use
- **SEE** — **pure pixels**: "CUA processes raw pixel data…perceives the browser screen as pixels." Explicit **Perception → Reasoning (inner monologue) → Action** loop; screenshots returned as `computer_call_output`. Raw **(x,y)** in screenshot space (no set-of-marks); 1440×900 recommended for click accuracy; remap coords if you downscale. (openai.com/index/computer-using-agent; developers.openai.com/.../tools-computer-use)
- **CLICK** — vocab: `click, double_click, drag, move, scroll, keypress, type, wait, screenshot` (newer models emit **batched `actions[]`**). **Synthetic** input — executor maps to **Playwright** (`page.mouse.click`, `keyboard.type`) or xdotool; the model "is never performing actions itself." Run in an **isolated browser/VM**, treat page content as untrusted. (learn.microsoft.com/.../openai/how-to/computer-use; openai-agents `ComputerTool`)
- **PLAN/MEMORY/LOOP** — planning + self-correction are model-native ("break tasks into multi-step plans and adaptively self-correct"). Cross-turn state via **`previous_response_id`** + carrying **reasoning items** forward; memory = accumulating screenshot+action history. **Max-iteration cap** "before returning control to a human supervisor"; loop ends when no `computer_call` is returned. **Test-time scaling**: more allowed steps → higher accuracy. (openai.com/index/computer-using-agent; learn.microsoft.com/.../computer-use)
- **HANDOFF** — **trained to proactively ask the user to take over for login, payment, and CAPTCHA.** **Takeover mode does NOT screenshot what the user enters** (credential privacy). Confirms before side-effects ("submitting an order or sending an email…ask for approval"). API mechanism = **`pending_safety_checks` → echo `acknowledged_safety_checks`** to continue (codes: `malicious_instructions`, `irrelevant_domain`, `sensitive_domain`); a separate **monitor model can pause the task**. Watch mode for sensitive domains. (openai.com/index/introducing-operator; learn.microsoft.com/.../computer-use)

### Vercel — AI SDK + `vercel-labs/agent-browser`
- **SEE** — the **AI SDK perceives nothing** (it's an orchestration loop); browser state returns as **typed tool results** (text or `{type:'image'}` base64 screenshots). The separate **`agent-browser`** driver (Rust + CDP) is **accessibility-tree-first** with compact **`@eN` refs** ("~200–400 tokens vs raw HTML"), with **screenshot (`--annotate` numbered overlay, `[N]`→`@eN`)** as the visual fallback — the *same refs key both modes*. (ai-sdk.dev/docs/agents/overview; github.com/vercel-labs/agent-browser SKILL.md)
- **CLICK** — actions are **typed tool calls the model emits**, executed by a dev-supplied `execute`. Provider **computer-use tool factories** (`anthropic.tools.computer_*`) emit `action`+`coordinate`/`text`; the SDK "never touches the OS itself." `agent-browser` acts via ref-targeted commands (`click @e2`, `fill @e3 "…"`). (ai-sdk.dev/.../tools-and-tool-calling; ai-sdk.dev/providers/.../anthropic)
- **PLAN/MEMORY/LOOP** — `ToolLoopAgent`: call LLM → run tools → **append results to history** → repeat. **Default `stopWhen: stepCountIs(20)`** "to prevent runaway loops"; also `hasToolCall`, token-**budget** stop. **`prepareStep`** (runs before each step) is the planning lever: **compact/trim history**, swap model, restrict tools, or force a tool. "`done`-tool with no `execute`" = clean explicit-completion signal. `DurableAgent` makes the loop resumable. (ai-sdk.dev/docs/agents/loop-control; vercel.com/blog/ai-sdk-6)
- **HANDOFF** — first-class HITL via **`needsApproval`** (bool or async, **risk-gated**: auto-run safe calls, gate sensitive ones). The SDK **pauses** and emits **`approval-requested`**; client calls **`addToolApprovalResponse({approved})`** to **resume**; a **denial is fed back as `output-denied`** so the model **re-plans** instead of hard-failing. (ai-sdk.dev/cookbook/next/human-in-the-loop; vercel.com/blog/ai-sdk-6)

### Vy by Vercept *(acquired by Anthropic 2026-02-25; standalone app wound down ~2026-03)*
- **SEE** — **vision-first, pixels not DOM**: "trained to understand the screen visually like human eyes rather than reading the…DOM." Proprietary **VyUI** grounding model maps language→on-screen elements (SOTA ScreenSpot numbers). **Runs natively on the user's real machine/screen**; frequent screenshots (~1.5–3s/step). (scb10x.com; together.ai/customers/vercept; geekwire.com)
- **CLICK** — **real OS-level mouse/keyboard** on the actual UI ("executes mouse or keyboard commands to mimic the way you'd control the computer"); **drives the user's real, already-logged-in sessions** ("no passwords are handed over"); works across browsers + native apps. Tradeoff: slower, can mis-click dense UIs. (geekwire.com; askbeevs.com; superbcrew.com)
- **PLAN/MEMORY/LOOP** — reasoning agents + visible **thought bubbles**; **Watch & Repeat** learns a task from one demonstration and **parameterizes** it for re-runs; opt-in **"remember snippets"** (address, IDs) for form-fill. **Recovery is human-assisted by design** — "if exceptions occur, the user intervenes and teaches it new steps"; independent tests found weak autonomous recovery on multi-window flows. (linkedin.com/posts/vercept; askbeevs.com; swfte.com)
- **HANDOFF** — explicit **red-button interrupt/takeover** any time (it holds mouse/keyboard while acting). Stance: **run on already-logged-in sessions, no credential handoff**; keep a human in the loop for high-risk (finance/health/law). (vercept.com/docs/vy-interface; vercept.com/human-readable-terms)

## 2. THE SHARED RECIPE  (present in ≥3 of 4 → we copy it)

- **S1 · SEE = screenshot is ground truth, re-taken every step.** All four perceive primarily by screenshot/vision (Operator & Vy pure pixels; Claude pixels +DOM; Vercel driver a11y-first but screenshot fallback). Re-screenshot after every action; **evaluate the new screenshot against the intended outcome — never assume the click worked** (Claude, explicit).
- **S2 · CLICK = small shared action vocab; model proposes, a trusted executor performs.** `click / type / scroll / key / navigate / wait / (drag) / answer`. The model never acts directly; a harness executes. Trust ranges synthetic (Operator/Playwright) → CDP (Claude-Chrome) → native OS (Vy).
- **S3 · LOOP = bounded, with a hard max-step cap.** Universal anti-runaway/anti-cost safeguard (Claude ≈10, Vercel =20, Operator "before returning to human"). Loop ends on explicit completion signal.
- **S4 · MEMORY = accumulating screenshot+action+reasoning history, ACTIVELY MANAGED.** Keep a **rolling buffer of the N most recent screenshots**, **replace older screenshots with text placeholders / a running summary**, compact past a threshold, and **carry the model's own reasoning forward** between steps (Operator reasoning items, Claude interleaved thinking, Vercel `prepareStep` compaction).
- **S5 · SELF-CORRECT = verify outcome, and when stuck SWITCH MODALITY.** Detect no-progress and change approach — switch from clicking to keyboard/scroll/DOM, or zoom/scroll to re-find the target (Claude tactic; Operator self-correct; everyone caps then escalates).
- **S6 · HANDOFF = login / payment / CAPTCHA always go to the human, as PAUSE→ASK→RESUME (not terminate).** Unanimous. The human's action/answer is **fed back to continue** the loop (Vercel `approval-requested`→`addToolApprovalResponse`; Operator `pending_safety_checks`→`acknowledged`; Claude Allow/Decline). **Takeover is private — do not capture/observe what the user types** (Operator). **Confirm before irreversible side-effects** (submit order / send). **Run in the user's real, logged-in session** so walls are rare to begin with (Vy, Claude-Chrome, us). **Never auto-enter credentials; never solve CAPTCHAs** (Operator + Claude prohibit it outright).

## 3. Map the shared recipe to OUR loop (`webvoyager.py`)

| # | Shared item | Our loop today | Gap → general change to COPY |
|---|---|---|---|
| S1 | screenshot every step + verify outcome | re-observe screenshot + set-of-marks each step; code-computed PROGRESS/NO_CHANGE/REGRESSION | **Have** the re-screenshot + a *stronger* (code-level) outcome check. **Add**: tell the model to confirm from the new screenshot whether its last action hit its intent. |
| S2 | small vocab, trusted executor | click/type/scroll/navigate/back/answer via extension **CDP trusted** input | **Have / ahead** (trusted CDP, not synthetic). No change. |
| S3 | bounded loop, max-step cap | `max_steps` overall + `per_subgoal` cap | **Have.** Minor: allow a touch more room on hard subgoals (test-time scaling). |
| S4 | managed rolling memory + reasoning carry-forward | last-5 action *strings* + single current screenshot; per-step `thought` discarded | **Biggest gap. Add**: a rolling running-summary of older steps (compaction) + carry the last `thought`(s) forward as a lightweight scratchpad. |
| S5 | verify + switch modality when stuck | forbid-repeat + 3-strike → reflect → fail-subgoal (code anti-loop, ahead) | **Have / ahead** on detection. **Add**: when stuck, nudge a *different action TYPE* (scroll/keyboard-enter/zoom/different element), not just a different index. |
| S6 | login/payment/captcha → pause→ask→resume; takeover privacy; never auto-cred/captcha | wall (BLOCK_MARKERS) → **terminal** `needs_human`; PURCHASE_GUARD stops before buy | **Core change. Build wall-handler stubs**: pause → **text the user** (ChannelStub) → save resume state → `/agent/resume` → continue. **Pause screenshots while the user enters credentials** (takeover privacy). Keep the hard line: never type passwords, never solve captchas. |

**Net:** we already match S1/S2/S3/S5 (and are *ahead* on trusted input + code-level anti-loop). The two general upgrades worth copying are **S4 (managed memory + reasoning carry-forward)** and **S6 (pause→ask→resume handoff with takeover privacy)**. Both are site-agnostic; anti-cheat grep stays clean.
