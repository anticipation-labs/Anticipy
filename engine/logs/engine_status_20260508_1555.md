## New failures discovered (and addressed)

### F-TBR-1 (FIXED): Browser-Use launch path was BLOCKING every scenario

Three nested bugs in the browser-launch path of `app.agent.execute_task`:

1. **BrowserStartEvent 30s timeout** — Chromium first-launch on this codespace
   exceeds 30s under load. Default browser-use 0.11.13 timeout was too tight.
   FIX: set env vars `TIMEOUT_BrowserStartEvent=90` /
   `TIMEOUT_BrowserLaunchEvent=90` at agent.py module load time.

2. **Half-initialized session is silent** — when start() raised TimeoutError,
   the existing retry loop fired, but reusing the same `BrowserSession` object
   leaves a corrupted bubus event-bus state. Re-calling start() returns
   normally with `cdp_client=None`; the agent then fires `navigate` against a
   dead CDP and gives up after 5 retries with no clear cause.
   FIX: probe `_get_cdp_client(session)` after start(). Treat `None` /
   AssertionError / timeout as a start failure. Construct a *fresh*
   BrowserSession on each retry attempt.

3. **Stable user-data-dir corruption** — when a launch fails, SingletonLock
   files persist in the user-data-dir and block subsequent launches against
   the same dir. Reusing the dir guarantees the next launch fails.
   FIX: `_clean_chromium_lock_files()` removes Singleton* files on retry.
   When a stable profile fails, fall back to a fresh ephemeral dir for the
   retry so the launch path can succeed even if the persistent dir is locked.
   Test harness updated: `test_torture_browser` now uses `user_id=None`
   (ephemeral profile per scenario) so failures don't cascade.

Verified: same code path that produced 0/9 PASS now produces 1/9 PASS
(graceful login-wall decline) plus 5 real agent-skill FAILs. Previously every
scenario hit "CDP client not initialized" and reported "I had trouble loading
the page".
