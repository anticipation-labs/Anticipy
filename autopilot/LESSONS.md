# LESSONS

Append here whenever a mistake repeats, then adjust the loop or docs so it is harder to repeat.

- 2026-06-06: Generated Codex build transcripts under `logs/codex/build_*.jsonl` mutate while a lap is still running. Do not track them as kept proof. Keep stable replay proof in `logs/trace/<lap>.jsonl`; ignore generated live transcripts.
- 2026-06-06: The amended judge required MP3 holdouts but the realday harness rejected audio while normal builder diffs were forbidden from touching the harness. Treat generic input-adapter fixes as control-plane plumbing, log them as not judged, and never count them as milestone proof until a later fresh judge lap passes.
- 2026-06-06: A verdict inventory list of holdout filenames was treated as if every listed file had been burned, leaving the judge with no selectable fresh day. Amendment 2 supersedes that burn model: failed or blocked judge runs do not burn held-out days. A held-out file rotates out only when it contributes to a milestone PASS.
- 2026-06-06: The system repeatedly typed the whole task into a browser search box and treated search/read/context proof as progress. This is not thinking. Fix the planner and routing boundary: explicit information lookup may search, but action tasks must decompose into API hands, the real browser agent, or ask/needs-human. Do not paper this over with more browser regexes.
- 2026-06-06: Stale eval proof from older laps leaked into fresh held-out planning. Treat previous-lap ids, old proof titles, and old sent-mail subjects as contamination. Current-lap planning must create fresh parameters from the current real need or abstain.
- 2026-06-06: Raw run artifacts were committed before Amendment 2: `logs/last_realday.json`, `logs/trace/*.jsonl`, and raw verdict JSON/JSONL can contain transcripts or held-out-derived evidence. Keep them local-only, ignore them, untrack them with `git rm --cached`, and amend or scrub branch history before judging.
- 2026-06-06: A guard-only slice can pass focused tests and still fail reality. Lap `20260606T113648Z` added a final completion guard, but the held-out judge still found internal `goal_done` entries with no artifact-shaped proof and no real external artifact. Do not spend another lap making internal proof rules look nicer. Route action tasks into API hands first, then the real browser agent hand, else explicit ask/needs-human.
- 2026-06-06: Live planner prompt/filter work alone did not fix reality. Lap `20260606T124709Z` stopped advertising internal support intents to OpenRouter, but the held-out judge still found 13 act goals marked done with zero steps and zero proof keys. The next slice must fix the actual zero-step completion path and force action goals into API/browser jobs or explicit wait/ask, not just change allowed intent text.
- 2026-06-07: A real API-created artifact is still fake if it is semantically wrong. Lap `20260606T151119Z` created and then cleaned up a Calendar item, but the judge found it used the capture timestamp window instead of the requested future-relative time. Never use capture time as event time unless the user clearly asked for now. If temporal semantics are ambiguous, wait or ask instead of creating a wrong artifact.
- 2026-06-07: Clean typed M0 failed because the harm-line returned `ask` for a safe, reversible `[Anticipy test]` Calendar instruction. Ask-only behavior is not progress. The next fix must teach the live path to recognize and complete safe, fully time-grounded, self-owned Calendar test tasks, then let the judge verify the real artifact.
- 2026-06-07: Clean typed M0 then failed after a build slice made the system return `act`: the goal was marked `done` with zero steps and empty proof, and no Calendar artifact existed. Empty plans must never complete action goals. Fix the planner/orchestrator boundary so a safe Calendar action becomes a real `create_event` step with proof, or the goal fails/waits loudly.
- 2026-06-07: M1 failed as `FAKE/TAMPER` when the judged executor commit contained only logs while actual production-linked product changes lived uncommitted in `/Users/omarebrahim/Developer/Anticipy-DEV-FINAL`. The judge also found owner/person-specific literals inside rebuilt packaged product archives. Next production work must be tracked in the source tree being judged, and packaged product code must be scrubbed of owner/person literals before packaging.
- 2026-06-08: A native Apple Calendar shortcut is unsafe during autonomous build if creation cannot be followed by reliable read-back and cleanup. A tagged test event may have been created, but macOS privacy blocked Calendar database access and AppleScript listing timed out. Do not use native local Calendar as the proof path unless read-back and deletion are reliable; prefer connector/API-verifiable surfaces or a browser flow that the judge can inspect and clean up.
- 2026-06-08: Do not grep or dump raw Chrome `Secure Preferences`. It can expose unrelated account/profile data in terminal output. For extension diagnostics, parse the JSON and print only the specific Anticipy extension id fields needed for the lap: path, enabled/disabled state, disable reasons, manifest version, and whether `nativeMessaging` is present.
- 2026-06-08: Use `apply_patch` for lap log edits too. A shell append is easy to miss in review and breaks the discipline of explicit file patches, even when the trace file is ignored.
- 2026-06-08: Public unauthenticated pages kept touching `127.0.0.1` before the user was signed in or had explicitly checked the local engine. That creates hidden CORS noise and can make the stranger path feel broken. Public pages should not auto-probe loopback on load; local-engine checks are explicit user actions, and submit paths must stop locally until readiness is known.
- 2026-06-09: The Next dev-server-after-production-build stale chunk failure repeated. New rule: once `npm run build` has run in the Next repo, stop any active `npm run dev` process before browser checks, then start a clean dev server. Do this even if the current page still appears to load.
- 2026-06-09: The local-env dump mistake repeated while checking Supabase public config. Do not run broad `rg` over `.env.local` or env backup files. If a public browser storage key is needed, derive it from the hostname already visible in code or parse only the exact non-secret field without printing values.
- 2026-06-09: A model that can answer tiny capped JSON probes is not necessarily a usable live browser planner. When provider credit only allows roughly 20 output tokens, stop the old heavy planner loop, but do not stop M3. Continue with cached observations, deterministic real-store DOM recipes, item matching, and tiny next-click decisions against real sites, all labeled `UNPROVEN-PENDING-JUDGE`.
- 2026-06-09: Do not print full memory context during builder probes. Use sanitized assertions that report resolution success, chosen surface type, and no-search behavior without dumping raw notes or history into terminal output or durable logs.
- 2026-06-09: Real store add-to-cart flows fail on variants and recommendations before they fail on clicks. Context-only browsing memories must never act by themselves, quantity and unit details must match exact product variants, and product-specific add buttons need strong item-token agreement before any real click.
- 2026-06-09: Do not run broad searches over `.anticipy` state. It can dump local task queues, memory, profile, browser-profile metadata, or other personal operational data into the terminal. Search only specific code files or top-level filenames needed for the lap.
- 2026-06-09: Cart badges and product-page add confirmations are mutation evidence, not completion proof. Final browser-hand completion must open the real cart page and match the requested item there; zero-count cart labels and search-result pages must never complete a cart task.
- 2026-06-09: Memory-to-intent can fail by polluting the item with the store name when a remembered line says "product on store." Strip the resolved host stem and dangling site prepositions before browser search, and keep contextual hints out of the item whenever possible.
- 2026-06-09: Generic option controls on real stores can masquerade as product links. A label like `Options` is not product identity, even if it points at a buyable product URL. Skip generic option labels and require a real product title or strong item-token evidence before any Add click.
- 2026-06-09: Product text can settle before the real Add to Cart control appears. If a product page has strong item evidence but no add control, re-observe the settled page once before scrolling. Otherwise the recipe can scroll past a late-rendered button and fail without needing to.
- 2026-06-09: Real-store product URL shapes drift. Best Buy moved useful product rows to `/product/...` URLs while the recipe only accepted the old `/site/.../*.p` shape. When a search page has strong product titles but `buyable_product_links=0`, inspect sanitized href shapes and update the generic product URL classifier instead of treating the store as linkless.
- 2026-06-09: Cart recommendation text can look like real cart contents after the page settles. IKEA put recommendation products after the actual cart item area, and broad cart windows falsely matched unrelated requested items. Final cart proof must isolate the actual item section with boundaries such as order summary or checkout, and token windows must stay item-sized.
- 2026-06-09: A hard-site browser failure must not become a fake human gate. Office Depot failed final cart verification after real Add attempts, but exhausted browser retries parked the goal as `waiting`/`needs_human`. True walls return `needs_human` from the hand. Ordinary exhausted retries must mark the step and goal `failed` so the loop keeps building instead of parking.
- 2026-06-09: Cart-page navigation text can still look like item evidence. REI's cart shell exposed category labels that overlapped with product tokens, while a durable cart read-back needed actual cart structure. Cart URL proof must require cart item structure such as checkout, subtotal, quantity, or remove before item tokens count.
- 2026-06-09: Fresh-open cart proof can still be false if it uses the same bridge instance and active target cache. Container Store looked durable inside the active bridge while a separate NativeBridgeLink read-back saw no cart item. Native-bridge known-cart proof must survive a separate fresh_probe observer before completing.
- 2026-06-09: Search-result fallback can silently drop important modifiers from a token-rich remembered item. Brand plus category is not enough when the memory includes material or feature words. For long item names, require high token overlap and keep leading distinctive tokens, or fail rather than add a broad substitute.
- 2026-06-09: A product URL slug can contradict the visible product page title. Do not combine URL tokens with visible title/text to make a product page look exact. The visible product identity must satisfy the token and distinctive-token bar by itself before any real Add click.
- 2026-06-09: Do not reward long product titles when token hits tie. A compact ordered item phrase should beat broad titles with scattered requested tokens, otherwise the hand can add a broader substitute even though the exact product is visible.
- 2026-06-09: A configured fresh Chrome profile path must be created before CDP launch. If the path is missing, the bridge can silently fall back to a weak surface with title/text but no actionable marks, making real-store product rows look absent.
- 2026-06-09: Check the page state after the final bounded scroll before failing a real-store search. Bookshop product rows appeared only after the last scroll, so a loop that scrolls and then immediately fails can miss the exact product. Also penalize unrequested variant words such as workbook, calendar, guide, and summary so add-on editions do not outrank the base item.
- 2026-06-09: Context hints are not product identity. A word like kit can explain why the user wanted the item, but it must not become an exclusive product filter that discards exact matches and selects a broader bundle or kit. Let hints adjust ranking only after exact item score and variant penalties.
- 2026-06-09: Adding a new cart URL shape can turn recommendation text into apparent cart proof if item evidence is only page-wide. When recognizing routes like Adorama `/cartview`, require item-local cart structure, such as quantity or remove, before cart-page item tokens count as proof.
